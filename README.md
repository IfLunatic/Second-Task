# Паралельне обчислення суми масиву методом хвильової редукції

> **Лабораторна робота з дисципліни «Паралельні та розподілені обчислення»**  
> Реалізації трьома мовами програмування: **Java**, **C# (.NET)**, **Go**.  
> Опрацювання масиву розміром **1 000 000 000** елементів (in-place).

---

## 1. Опис та математична модель алгоритму

Алгоритм обчислює суму $N$ елементів масиву методом **хвильової редукції (wave reduction)** без виділення додаткової пам'яті (in-place):

1. **Хвильовий процес**: На кожній хвилі елемент першої половини $i$ додається до симетричного елемента другої половини $j = n - 1 - i$, де $n$ — актуальна довжина масиву на поточній хвилі.
2. **Запис на місці**: Результат записується в менший індекс: `array[i] = array[i] + array[j]`.
3. **Обробка непарної довжини**: Якщо $n$ непарне, центральний елемент без пари `array[⌊n/2⌋]` залишається без змін і переходить у наступну хвилю.
4. **Редукція розміру**: Після завершення поточної хвилі актуальна довжина стає $\lceil n / 2 \rceil = (n + 1) / 2$.
5. **Критерій завершення**: Алгоритм зупиняється при $n = 1$. Кінцева сума зберігається в `array[0]`.
6. **Кількість хвиль**: $K = \lceil \log_2 N \rceil$. Для $N = 10^9$ потрібно рівно **30 хвиль**.

### Математичний інваріант
Сума елементів зберігається після кожної хвилі:

$$
\sum_{k=0}^{\lceil n/2 \rceil - 1} \text{array}_{\text{new}}[k] = \sum_{k=0}^{n-1} \text{array}_{\text{old}}[k]
$$

### Контрольна сума для тестування ($1, 2, \dots, N$)

$$
S = \frac{N \times (N + 1)}{2}
$$

Для $N = 1\,000\,000\,000$:

$$
S = \frac{10^9 \times 10^9 + 10^9}{2} = 500\,000\,000\,500\,000\,000
$$

## 6. Порівняння багатопотокових підходів

| Критерій | Java | C# | Go |
|---|---|---|---|
| **Примітив багатопоточності** | `ExecutorService` (FixedThreadPool) | `Task.Run` + `ThreadPool` | `goroutine` (легковагі горутини) |
| **Синхронізація між хвилями** | `CountDownLatch` (на кожну хвилю) | `Task.WaitAll` | `sync.WaitGroup` |
| **Передача завдань** | Внутрішня черга пулу | Планувальник задач .NET | Буферизований канал `chan WorkItem` |
| **Вага одиниці виконання** | ≈ 1 МБ (потік ОС) | ≈ 1 МБ (потік ThreadPool) | ≈ 2–4 КБ (динамічний стек) |
| **Захист від перегонів** | Чанкування неперетинних індексів | Чанкування + локальні змінні замикання | Чанкування неперетинних індексів |
| **Очищення ресурсів** | `executor.shutdown()` | Автоматично середовищем CLR | `close(workChan)` |

### 7.1. Промпт №1: Архітектурний системний промпт (Master Architecture Prompt)

Використовується для первинного проектування та узгодження математичної моделі:

```text
Ти — провідний системний архітектор та викладач курсу «Паралельні та розподілені обчислення».
Мені потрібно спроектувати багатопотоковий алгоритм обчислення суми масиву методом хвильової редукції для трьох мов: Java, C#, Go.
Розмір масиву — 1 000 000 000 елементів.

Правила алгоритму:
1. Масив розміром N зменшується хвилями.
2. На кожній хвилі елемент i додається до симетричного j = n - 1 - i, результат записується в array[i].
3. Якщо актуальна довжина n непарна, центральний елемент без пари лишається без змін.
4. Нова довжина стає ceil(n / 2). Хвилі повторюються до n = 1.
5. Фінальна сума знаходиться в array[0].

Вимоги до архітектури:
- Алгоритм має працювати strictly in-place (без дублювання 8 ГБ масиву).
- Пул робочих потоків/горутин створюється один раз і перевикористовується між хвилями.
- Синхронізація між хвилями без глобальних блокувань додавання (lock-free для окремих пар).
- Розподіл пар на неперетинні безперервні блоки (чанки) для усунення False Sharing.
- Використання 64-бітних цілих чисел (long / int64) для запобігання переповнення.
- Доведи математичну коректність (інваріант суми) та наведи формулу аналітичної перевірки.
```

## 8. Типові помилки студентів та способи їх уникнення

1. **Створення потоку на кожну пару**: Спроба створити 500 млн потоків на 1-й хвилі призводить до аварійного вичерпання пам'яті ОС.

2. **Відсутність міжхвильового бар'єра**: Хвиля $k+1$ стартує до завершення хвилі $k$, викликаючи пошкодження даних.

   *Рішення: локальна копія всередині циклу.*
4. **Помилка виклику `wg.Add()` у Go**: Виклик `Add()` після запису в канал веде до від'ємного лічильника і паніки.  
   *Рішення: `wg.Add()` суворо перед `workChan <-`.*
5. **Витік пулу / горутин**: Не викликано `shutdown()` у Java або `close()` у Go. Процес зависає після завершення обчислень.

## 9. Питання для захисту лабораторної роботи (FAQ)

1. **П: Чому операція `array[i] += array[j]` не потребує `lock` / `synchronized`?**  
   *В:* Індекси $i$ належать лівій половині ($0 \le i < n/2$), а $j$ — правій ($j \ge n/2$). Потоки обробляють неперетинні діапазони індексів $i$, тому одночасний запис в одну й ту саму комірку неможливий.
2. **П: Що відбувається з центральним елементом при непарній довжині $n$?**  
   *В:* Елемент з індексом $\lfloor n/2 \rfloor$ не має пари. Він не модифікується і автоматично входить у наступну хвилю, оскільки нова довжина обчислюється як $\lceil n/2 \rceil = (n + 1) / 2$.
3. **П: Чому при 12 ядрах прискорення становить лише ≈ 2.3×, а не 12×?**  
   *В:* Алгоритм обмежений пропускною здатністю підсистеми пам'яті (Memory-Bound). Шина пам'яті насичується вже при 4–8 потоках.
4. **П: Чим відрізняється робота з пам'яттю масиву в Java та Go?**  
   *В:* У Java `long[]` є об'єктом на купі (heap), адресованим через заголовок об'єкта. У Go слайс `[]int64` — це легковажна 24-байтна структура зі вказівника на масив, довжини (`len`) та ємності (`cap`).
5. **П: Скільки операцій додавання виконує алгоритм сумарно?**  
   *В:* Рівно $N - 1$ операцій (сума спадної геометричної прогресії $N/2 + N/4 + \dots + 1$).
